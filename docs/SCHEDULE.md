# Масштабування за розкладом (бонус 8)

Terraform: `aws_appautoscaling_scheduled_action.day` / `.night` у [`infra/autoscaling.tf`](../infra/autoscaling.tf).
Вмикається змінною (за замовчуванням вимкнено, щоб під час лабораторних тестів мінімум був 1):

```hcl
# terraform.tfvars
schedule_enabled   = true
schedule_day_min   = 2
schedule_night_min = 1
```

| Дія | Розклад (`Europe/Kiev`) | min / max |
|---|---|---|
| day | `cron(0 8 ? * MON-FRI *)` — 08:00 у робочі дні | 2 / 4 |
| night | `cron(0 20 ? * * *)` — 20:00 щодня | 1 / 4 |

Scheduled action змінює `min_capacity` цілі масштабування; target tracking за CPU працює далі в межах [min, max].
У п'ятницю о 20:00 мінімум стає 1 і залишається таким усі вихідні до понеділка 08:00.

Перевірка: `aws application-autoscaling describe-scheduled-actions --service-namespace ecs`.

Примітка: після спрацювання розкладу `terraform plan` показує drift `min_capacity` у `aws_appautoscaling_target.app` —
`apply` поверне значення з `autoscaling_min` до наступного спрацювання cron.

## Чому не 0 уночі

ECS дозволяє `desiredCount = 0`, але за ALB це означає 503 на кожен запит, поки хтось вручну або за розкладом не
підніме задачу: у ECS немає «пробудження за запитом» (на відміну від Cloud Run / Container Apps / Lambda, де холодний
старт запускає екземпляр автоматично). Target tracking за CPU не масштабує з 0 (немає задач — немає метрики CPU).
Тому мінімум уночі — 1. Для довідки: холодний старт задачі Fargate (з 0 до готовності) — 1–2 хв (виділення ресурсів,
pull образу ~60 MB, старт uvicorn, 2 health check ALB по 15 с).

## Місячна економія

Задача: 0.25 vCPU + 0.5 GB. Ціни Fargate Linux/x86 (us-east-1, для eu-north-1 уточнити на
[aws.amazon.com/fargate/pricing](https://aws.amazon.com/fargate/pricing/)): $0.04048 за vCPU·год, $0.004445 за GB·год.

```
вартість задачі = 0.25 × 0.04048 + 0.5 × 0.004445 = $0.01234 / год
місяць = 730 год; робочих днів ≈ 21.7; «денних» годин = 21.7 × 12 = 260 год; решта = 470 год
```

| Варіант | Задачо-годин мінімуму | Вартість мінімуму / міс |
|---|---|---|
| Завжди min = 2 (без розкладу, «на всяк випадок») | 2 × 730 = 1460 | $18.02 |
| **Розклад: 2 удень, 1 уночі й у вихідні** | 2 × 260 + 1 × 470 = 990 | **$12.22** |
| Завжди min = 1 | 730 | $9.01 |

**Економія розкладу проти постійних 2 задач: 470 задачо-год × $0.01234 ≈ $5.80/міс (≈32 %).**
Порівняно з постійним min = 1 розклад коштує на $3.21/міс більше, натомість удень сервіс має гарячий резерв
(друга задача в іншій AZ — відмова однієї задачі/зони не призводить до простою, а пік не чекає 3–5 хв на scale-out).
Додаткові задачі від target tracking оплачуються в обох варіантах однаково.
